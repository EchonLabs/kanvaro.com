# Task 0.6 — Tool catalogue

**Status:** draft for approval, 20 Nov 2026
**Based on:**
- The decision record (0.4): everything in Kanvaro is in release 1, in three waves, with
  grouped tools.
- An extracted inventory of all 332 Kanvaro API handlers
  ([tools/route-inventory.mjs](../../tools/route-inventory.mjs)).
- The live checks in 0.5.

**Reading the tables**
- *Route* is relative to `/api`.
- *Permission* is the Kanvaro permission the route checks. Kanvaro enforces it, and the
  MCP server does not repeat the check.
- *Inputs* is the **allow-list**: the only fields the tool accepts and sends.
- The server always adds `page` and `limit` (default 25, maximum 100) to list calls, and
  never takes `organizationId` or another user's `userId` from tool input.

## 5. Response filters

Each tool returns only the fields an AI needs. These are always removed:

| Field | Where it appears |
|---|---|
| `password`, `passwordResetOtp`, `passwordResetToken`, `passwordResetExpiry` | `members`, any populated user |
| `hourlyRate`, `billingRate`, `memberRates` | `projects/{id}`, `members`, users — kept only in `finance_get` and `reports` (financial) |
| Holiday API key | `organization/holiday-sets/api-key` (never returned; only "set / not set") |
| `__v`, internal counters, `_counterRollbackProject` | everywhere |

User objects are reduced to `id`, `name`, `email`, `role`.
