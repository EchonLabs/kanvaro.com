# Task 0.5 — Route authentication check on a running Kanvaro

**Status:** done, 20 Nov 2026
**Instance:** local Kanvaro v1.52.0 (`next dev`, database `kanvaro2`, one organisation)
**Method:**
- One test user per role, created with [tools/seed-test-users.cjs](../../tools/seed-test-users.cjs).
- Signed in through Kanvaro's real `/api/auth/login`.
- Every GET route called three ways (no auth / Bearer only / cookie only) with
  [tools/route-check.mjs](../../tools/route-check.mjs), plus per-role checks with
  [tools/role-spot-check.mjs](../../tools/role-spot-check.mjs).

Write routes (POST/PUT/PATCH/DELETE) were **not** called, to avoid changing data. They
use the same authentication code as the GET handler in the same file. The two
exceptions found by code review are marked below.

| `time-tracking/reports` | Organisation time report | High |

## 4. Default refresh-token key (new, critical)

- The code reads `JWT_REFRESH_SECRET` and falls back to `'your-refresh-secret-key'`.
- `.env.local`, `env.example`, `docker-compose.yml` and **`docker-compose.prod.yml`** set
  `REFRESH_TOKEN_SECRET`, a name the code never reads.
- `config.production.env` uses the right name, but it is only used if someone copies it
  to `.env.production` by hand.

**Test on the local instance:**
1. Signed a refresh token for the test viewer with the default key.
2. Sent it as a cookie to `/api/auth/permissions` → **200** (control with no token: 401).

**Consequence:** where the variable name is wrong, anyone who knows a user ID can sign in
as that user. User IDs are visible through the unauthenticated search (profile links).
So someone with no account could sign in as the admin.

**To check on every real deployment now:** is `JWT_REFRESH_SECRET` set in the running
container's environment? If not, set it, then restart Kanvaro. This also logs everyone out.

## 6. Kanvaro fixes — updated list (adds to the 0.4 record)

| # | Fix | Severity |
|---|---|---|
| **F0** | Use `JWT_REFRESH_SECRET` consistently (or make the code read `REFRESH_TOKEN_SECRET` too); **refuse to start** if either JWT secret is missing or set to the default | **Critical — check production today** |
| F1 | `/api/members`: return only safe fields | Critical |
| **F9** | `settings/email` and `settings/database`: require an admin; never return secrets (return "set / not set"); rotate the Azure client secret on any instance where this was reachable | **Critical** |
| F2 | Time-tracking `logs`, `timer`, `reports`, `reports/budget`: require sign-in; take the user and organisation from the session | Critical |
| **F10** | `test-connection`: require an admin, or remove it after setup | High |
| F3 | `auth/me`, `entries`, `entries/[id]`, `hr/*`, `bulk-upload`: use the shared helper | High |
| F4 | `search`: require sign-in, limit results to the caller's projects, return no users to roles without team access, escape the search text | High |
| F5–F8 | As in the 0.4 record | — |
